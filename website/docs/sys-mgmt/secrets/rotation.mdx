Rotation is manual. authentik does not schedule or automatically rotate secrets.

Rotating replaces a [secret](./index.mdx)'s value with a freshly generated one. Only text secrets can be rotated; multi-line and file secrets keep their value until you change it by hand.

Rotation changes the value for every object referencing the secret. Update every external client that uses it. Connected outposts are notified after the change is committed and use the new value after reloading their configuration.

Rotating a secret used for proxy cookies invalidates all sessions for the proxy providers that use it. Users must sign in again.

:::warning Rotating secrets generated by other systems
Only rotate a secret whose value was issued by another system, such as an OAuth source consumer secret or an SMTP password, if that system accepts values generated by authentik. In most cases, it will not.

See [Secrets authentik does not generate](./index.mdx#secrets-authentik-does-not-generate).
:::

Under **System** > **Secrets**, click **Rotate secret**, then **Rotate** to confirm. This takes the **Rotate secret's value** permission.

Forms that select a text secret expose the same action beside the selector. Rotation takes effect even if you cancel the surrounding form. If you also have the **View secret's value** permission, authentik provides the new value after rotation so you can copy it to the client. The value stays masked until you reveal it; you can copy it while it is masked.

## Auditing

Rotation and explicit value replacement are recorded as a [`secret_rotate`](../events/event-actions.mdx#secret_rotate) event.
