The `secret` reference field on the consuming object is the only way to set a credential through the API. The previous string fields (`client_secret`, `shared_secret`, `bind_password`, `token`, and the like) were removed in 2026.11: create or look up a [Secret](./index.mdx) and set the reference instead.

Reading a value goes through the secret's `view_value` endpoint. It takes the **View secret's value** permission and is recorded as a [`secret_view`](../events/event-actions.mdx#secret_view) event. The `rotate` endpoint replaces the value with a generated one. Updating `value` explicitly takes the same rotate permission. Both operations are audited; see [Rotate a secret](./rotation.mdx).

## Blueprints

In a [blueprint](../../customize/blueprints/index.mdx), define the secret as its own entry and reference it from the consuming object with [`!KeyOf`](../../customize/blueprints/v1/tags.mdx#keyof). Omit `value` to have authentik generate one server-side.

**Example**:

```yaml
- model: authentik_secrets.secret
  id: my-client-secret
  identifiers:
      name: my-app client secret
  attrs:
      value: hunter2 # omit to generate a value server-side
- model: authentik_providers_oauth2.oauth2provider
  identifiers:
      name: my-app
  attrs:
      secret: !KeyOf my-client-secret
```

To reference a secret that already exists, use [`!Find`](../../customize/blueprints/v1/tags.mdx#find) instead:

```yaml
- model: authentik_providers_oauth2.oauth2provider
  identifiers:
      name: my-app
  attrs:
      secret: !Find [authentik_secrets.secret, [name, my-app client secret]]
```
