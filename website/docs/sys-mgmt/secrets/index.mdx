A **Secret** holds a single value that other objects authenticate with, such as an OAuth2 provider's client secret, an LDAP source's bind password, or an SMTP password. Keeping the value in an object of its own means it can be shared, permissioned, and rotated in one place, instead of living inside each object that uses it. Objects reference the secret they use; see [which objects reference secrets](#objects-that-reference-secrets) below.

Manage secrets under **System** > **Secrets** in the Admin interface, or through the [API](./api-and-blueprints.mdx). Forms that reference a secret can also create one on the fly, and an OAuth2 or RADIUS provider created without one gets a secret with a generated value automatically.

## Types

A secret has one of three types, chosen when it is created:

- **Text**: a single-line value. This is the only type whose value authentik can generate and [rotate](./rotation.mdx).
- **Multi-line text**: a value spanning several lines, such as a PEM-encoded key or a JSON credential.
- **File**: an uploaded file, stored base64-encoded.

The type cannot be changed after the secret is created.

## Values

The value of a text secret is generated server-side, so you get a secret of known strength without reaching for `openssl rand`. Setting a value by hand is only needed when the secret has to match one that already exists elsewhere.

Reading a value is an audited act of its own: it takes the **View secret's value** permission, goes through a separate API endpoint, and is recorded as a [`secret_view`](../events/event-actions.mdx#secret_view) event.

## Permissions

Secrets use authentik's usual [permission system](../../users-sources/access-control/permissions.mdx), globally and per object. Beyond the standard add/change/delete/view set, two permissions apply to the value itself:

- **View secret's value**: read the value.
- **Rotate secret's value**: replace the value, either explicitly or with a generated one; see [Rotate a secret](./rotation.mdx).

## Objects that reference secrets

The following objects store their credentials as a reference to a secret:

- OAuth2 providers (client secret)
- RADIUS providers (shared secret)
- LDAP and Kerberos sources (bind and sync passwords)
- OAuth, Plex, and Telegram sources (consumer secrets and tokens)
- SCIM providers (token)
- Duo, captcha, SMS, and email stages (API credentials and SMTP passwords)
- Notification transports (webhook URL)
- Microsoft Entra and Fleet enterprise integrations (credentials)

## Secrets authentik does not generate

Credentials issued by another system, such as an OAuth source's consumer secret, an LDAP bind password, a Duo API key, or an SMTP password, are also stored as secrets. Create a secret containing the external value from the referencing form. Do not use the rotate action unless the other system accepts a value generated by authentik.
