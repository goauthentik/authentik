A secret holds a credential, such as an OAuth2 client secret, LDAP bind password, or SMTP password. Objects reference the secret, so they can share its value and use its permissions.

Manage secrets under **System** > **Secrets** in the Admin interface, or through the [API](./api-and-blueprints.mdx). Forms that reference a secret can also create one directly. If you create an OAuth2 or RADIUS provider without specifying a secret, authentik automatically creates a secret with a generated value.

:::warning Secret storage
authentik does not encrypt secret values in the database. File values are base64-encoded, which is not encryption. Protect database access and backups accordingly.
:::

## Types

A secret has one of three types, chosen when it is created:

- **Text**: a single-line value. This is the only type whose value authentik can generate and [rotate](./rotation.mdx).
- **Multi-line text**: a value spanning several lines, such as a PEM-encoded key or a JSON credential.
- **File**: an uploaded file, stored base64-encoded.

The type cannot be changed after the secret is created. Passwords, tokens, and client secrets require **Text** secrets. Apple OAuth sources require a **Multi-line text** secret containing the signing key. Google service account credentials, Kubernetes kubeconfig, and Kerberos keytabs and credential caches require **Multi-line text** or **File** secrets.

For Google service account credentials and Kubernetes kubeconfig, use multi-line text containing JSON or YAML, or upload the configuration as a file. For Kerberos keytabs, upload a file or create a **Multi-line text** secret containing base64 data or a `TYPE:residual` reference. For credential caches, upload a file or use a **Multi-line text** secret containing a `TYPE:residual` reference.

## Values

When creating a text secret, leave **Value** empty to automatically generate a value. Enter an existing credential when it was issued by another system.

Use **View secret** to view and copy a text value, or **Download secret** to download a file. To replace a text or multi-line value, click **Edit**, then **Modify**, and enter **New value**. To replace a file, select **New file** in the edit form. Leaving it empty keeps the current value.

Viewing or downloading a value requires the **View secret's value** permission and is recorded as a [`secret_view`](../events/event-actions.mdx#secret_view) event.

## Permissions

You can grant access to a secret's name separately from access to its value. Replacing or rotating a value requires its own permission, and editing an object that uses a secret does not automatically grant access to the credential.

See [Secret permissions](./permissions.mdx) for the permissions needed for each task, examples of roles, and how access works when objects share a secret.

## Objects that reference secrets

The following objects store their credentials as a reference to a secret:

- OAuth2 and Proxy providers (client and cookie secrets)
- RADIUS providers (shared secret)
- LDAP sources (bind password)
- Kerberos sources (sync password, keytabs, and credential caches)
- OAuth, Plex, and Telegram sources (consumer secrets and tokens)
- SCIM providers (token and Basic authentication password)
- Duo, captcha, SMS, and email stages (API credentials and SMTP passwords)
- Notification transports (webhook URL)
- Microsoft Entra and Fleet enterprise integrations (credentials)
- Google Workspace providers and Google Chrome Device Trust connectors and stages (service account credentials)
- Kubernetes service connections (kubeconfig)

## Secrets authentik does not generate

Credentials issued by another system, such as an OAuth source's consumer secret, an LDAP bind password, a Duo API key, or an SMTP password, are also stored as secrets. Create a secret containing the external value from the referencing form. Do not use the rotate action unless the other system accepts a value generated by authentik.
