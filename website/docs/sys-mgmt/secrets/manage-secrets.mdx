A secret is a named credential that you select when configuring another object. For example, an LDAP source selects a secret containing its bind password, and an email stage selects one containing its SMTP password. You manage the value under **System** > **Secrets**, while the source or stage keeps its connection settings.

You need permission to manage the object and permission to use the secret. Being able to edit a provider or source does not automatically let you read or replace its credential. See [Secret permissions](./permissions.mdx) for the permissions required for each task.

## Create a secret while configuring an object

1. Open the provider, source, stage, or connector form.
2. Beside its credential selector, click **Create secret**.
3. Give the secret a name that describes its purpose, such as `Production LDAP bind password`. Do not put the password itself in the name.
4. Enter the credential's value. If another system issued it, use that system's value. For a text credential that you want authentik to generate, leave **Value** empty.
5. Create the secret, then save the surrounding object form.

The selector only offers types supported by that field. For example, an OAuth2 provider takes a text secret, while a Kubernetes service connection accepts a multi-line or file secret containing its kubeconfig.

Creating the secret saves it immediately. Canceling the surrounding provider or source form does not delete the new secret. You can find it under **System** > **Secrets** and reuse it later.

To prepare a credential before configuring an object, create it under **System** > **Secrets** instead. Choose its [type](./index.mdx#types), then enter or upload its value. authentik does not encrypt these values in the database; see [Secret storage](./index.mdx).

## Select or reuse an existing secret

Open the object's credential selector, search for the secret by name, select it, and save the object. The selection links the object to that secret. It does not make a copy.

For example, two email stages can select the same SMTP password secret when they use the same SMTP account. Replacing that secret's value updates the credential used by both stages. Their SMTP hostnames and usernames remain separate settings on each stage.

Use separate secrets when credentials need independent changes or permissions. A shared secret has one set of permissions for all its uses. Granting someone permission to replace it lets them affect every object using it, even if they cannot edit those objects.

If a secret is missing from the selector, check that its type matches the field and that you have permission to view it. Selecting a different secret also requires permission to view its value. See [Working with other objects](./permissions.mdx#working-with-other-objects).

## Replace a credential issued by another system

When an external service gives you a new password, token, or credential file:

1. Open **System** > **Secrets** and find the secret used by the affected objects.
2. Click **Edit**. For text and multi-line secrets, click **Modify** and enter **New value**. For a file secret, select **New file**.
3. Save the secret, then check that the affected integration works with the new credential.

Leaving the value empty keeps the current value. Replacing a shared value affects every object using that secret. Coordinate the change with the external service to avoid interrupting connections.

To change just one object's credential, create a separate secret and select it on that object. The other objects continue to use the original secret.

The **Rotate secret** action generates a new text value in authentik. It does not ask the external service to issue or accept that value. Use [rotation](./rotation.mdx) only when you can configure the other system to use the generated value.

## Remove an unused secret

Select the secret under **System** > **Secrets** and click **Delete**. The confirmation shows objects that still use it. authentik prevents deletion while any object references the secret.

First change those objects to use another secret, clear their credential selection if the field is optional, or delete the objects. Then delete the unused secret. Deleting an object does not delete its secret, because another object can reuse it.
