This page sets up the backend, worker, and web UI on your machine. To work only on the UI against a containerized backend, use the [frontend development environment](./frontend-dev-environment.mdx) instead.

authentik is a Django application served by gunicorn behind a Rust front server, which also serves the static files. Background tasks run in a Dramatiq worker that uses PostgreSQL as its broker.

## Prerequisites

- [Python](https://www.python.org/) 3.14 and [uv](https://docs.astral.sh/uv/getting-started/installation/)
- [Rust](https://rust-lang.org/learn/get-started/) through rustup. The repository's `rust-toolchain.toml` pins the version; formatting also needs the nightly toolchain.
- [Go](https://go.dev/) 1.26 or later, for the outposts
- [Node.js](https://nodejs.org/en) 24 or later, installed with [nvm](https://github.com/nvm-sh/nvm), and [pnpm](https://pnpm.io/installation). pnpm switches itself to the version pinned in `package.json`.
- [Docker](https://www.docker.com/) with Compose v2
- [Make](https://www.gnu.org/software/make/) and [CMake](https://cmake.org/)

Run every command on this page from the root of your authentik checkout.

The PostgreSQL client tools are needed on the host: `make dev-reset` calls `dropdb` and `createdb`.

## 2. Start the services

```shell
docker compose -f scripts/compose.yml up -d
```

This starts PostgreSQL and a [Zenko CloudServer](https://www.zenko.io/cloudserver/) for S3-compatible storage.

## 3. Install and configure

```shell
nvm install 24 && nvm use 24
make install
make gen-dev-config
make migrate
```

`make install` installs the JavaScript and Python dependencies. `make gen-dev-config` writes `local.env.yml`, which you can edit for local overrides; rerunning it overwrites the file. To start over later, `make dev-reset` drops the database and migrates it again.

## 4. Build the UI and run authentik

No compiled UI ships in the repository, so build it once even if you only work on the backend:

```shell
make web-build
make run
```

The first start applies the default blueprints and works through the initial task queue, which takes a minute. Then open http://localhost:9000 and follow the prompts to set a password for **akadmin**.

While you work:

- `make run-watch` restarts the server and worker when `.py` or `.rs` files change. It needs [watchexec](https://github.com/watchexec/watchexec).
- `make web-watch` rebuilds the UI on save and reloads the browser.

If you lock yourself out, create a [recovery key](../../troubleshooting/login.mdx).

## End-to-end tests

authentik has two end-to-end suites, both run by `ci-main.yml`:

- **Selenium** (`tests/e2e/`), the `test-e2e` jobs.
- **Playwright** (`web/test/browser/`), the `test-e2e (web)` job. It runs against a live server.

### Selenium

```shell
COMPOSE_PROFILES=selenium docker compose -f tests/e2e/compose.yml up -d
make web-build
pnpm --dir web run build:sfe
make test tests/e2e/test_flows_login.py
```

Watch the browser at http://localhost:7900 (password `secret`), or over VNC on port 5900.

:::info
Docker Desktop needs host networking: **Settings** > **Resources** > **Network** > **Enable host networking**.
:::

### Playwright

The suite logs in to `http://localhost:9000` (override with `AK_TEST_RUNNER_PAGE_URL`) as `test-admin@goauthentik.io` with the password `test-runner`. Set those bootstrap credentials before authentik first starts; the bootstrap blueprint applies them only while **akadmin** has no usable password:

```shell
export AUTHENTIK_BOOTSTRAP_EMAIL=test-admin@goauthentik.io
export AUTHENTIK_BOOTSTRAP_PASSWORD=test-runner
make run
```

Then install the browser once and run the suite:

```shell
pnpm --dir web exec playwright install --with-deps chromium
pnpm --dir web run test:e2e
```

After a failure, `pnpm --dir web exec playwright show-report` opens the traces and screenshots. CI uploads the same files as the `playwright-report` and `playwright-traces` artifacts.
