An LDAP source connects authentik to an existing LDAP directory to synchronize users and groups. It can also write password changes back to the directory and, when configured in an authentication flow, authenticate users with their LDAP credentials.

:::info
For Active Directory, follow the [Active Directory integration](../../directory-sync/active-directory/index.mdx).

For FreeIPA, follow the [FreeIPA integration](../../directory-sync/freeipa/index.mdx).
:::

## Configuration options for LDAP sources

To create or edit an LDAP source, open the authentik Admin interface and navigate to **Directory** > **Federation and Social login**. Use the following settings to create a source or update an existing one.

| Setting                                     | Description                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Enabled**                                 | Toggle this option on to allow authentik to use the defined LDAP source.                                                                                                                                                                                                                                                                                                                           |
| **Update internal password on login**       | When the user logs in to authentik using the LDAP password backend, the password is stored as a hashed value in authentik. Disabled by default for new sources. See [Password login](#password-login) for the behavior and security considerations.                                                                                                                                                |
| **Sync users**                              | Enable or disable user synchronization between authentik and the LDAP source.                                                                                                                                                                                                                                                                                                                      |
| **User password writeback**                 | Enabled by default. Disable unless you want password changes made in authentik to be written back to LDAP. Only one LDAP source can have this enabled. Writeback requires appropriate directory permissions and authentik to receive the raw password; [hashed-password imports](../../../../install-config/automated-install.mdx#authentik_bootstrap_password_hash) are not written back to LDAP. |
| **Sync groups**                             | Enable or disable group synchronization between authentik and the LDAP source.                                                                                                                                                                                                                                                                                                                     |
| **Sync Group Hierarchy**:ak-version[2026.8] | Synchronizes parent and child relationships between LDAP groups by reusing the source's [membership configuration](#group-membership-and-hierarchy). This setting requires **Sync groups** to be enabled.                                                                                                                                                                                          |
| **Delete Not Found Objects**                | Deletes previously synchronized users and groups that are no longer found by the source's LDAP searches. Review the [deletion behavior](#delete-not-found-objects) before enabling.                                                                                                                                                                                                                |

### Connection settings

| Setting                                   | Description                                                                                                                                                                                                                                                                |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Server URI**                            | URI to your LDAP server or domain controller. You can specify multiple servers by separating URIs with a comma, such as `ldap://ldap1.company,ldap://ldap2.company`. When using a DNS entry with multiple records, authentik selects a random entry when first connecting. |
| **Enable StartTLS**                       | Enable to upgrade a `ldap://` connection to TLS before binding. Leave disabled for LDAP without StartTLS or for LDAPS (`ldaps://`).                                                                                                                                        |
| **Use Server URI for SNI verification**   | Sends the hostname from **Server URI** as the TLS Server Name Indication (SNI). Enable when the LDAP server requires SNI. Required for servers using TLS 1.3+.                                                                                                             |
| **TLS Verification Certificate**          | Optionally, select a certificate/keypair containing the LDAP server CA chain to validate the remote certificate. Leave this field empty to skip certificate validation for LDAPS and StartTLS connections.                                                                 |
| **TLS Client authentication certificate** | Client certificate and key pair used to authenticate to the LDAP server.                                                                                                                                                                                                   |
| **Bind CN**                               | Identifier used to authenticate the bind account. This is typically the bind account's distinguished name (DN) or another identifier supported by the directory, such as an Active Directory user principal name (UPN) in the format `user@domain.tld`.                    |
| **Bind Password**                         | Password used during the bind process.                                                                                                                                                                                                                                     |
| **Base DN**                               | Base distinguished name for synchronization searches. **Additional User DN** and **Additional Group DN** narrow the user and group search bases, respectively.                                                                                                             |

:::info TLS handshake failures
If the LDAP server rejects the TLS handshake, verify that **Server URI**, **Enable StartTLS**, and **Use Server URI for SNI verification** match the server configuration. You can also configure `AUTHENTIK_LDAP__TLS__CIPHERS` if the server requires a specific cipher suite.
:::

### LDAP attribute mapping

| Setting                                                    | Description                                                                                                                                                                                                                                         |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **User Property Mappings** and **Group Property Mappings** | Define which LDAP properties map to which authentik properties. For a new source, the Admin interface preselects the generic LDAP and Active Directory mappings. See also our documentation on [property mappings](#ldap-source-property-mappings). |

| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **User path**                   | Base path template for synchronized users, including existing users. | **Additional User DN**          | Prepended to the base DN for user queries.                                                                                                                                                                                                                                                                                                                                   |
| **Additional Group DN**         | Prepended to the base DN for group queries.                                                                                                                                                                                                                                                                                                                                  |
| **User object filter**          | Consider objects matching this filter to be users.                                                                                                                                                                                                                                                                                                                           |
| **Group object filter**         | Consider objects matching this filter to be groups.                                                                                                                                                                                                                                                                                                                          |
| **Group membership field**      | LDAP attribute or directory-specific expression used to discover memberships. Its meaning depends on the lookup direction.                                                                                                                                                                                                                                                   |
| **User membership attribute**   | Attribute on authentik users used for membership matching. In group-based lookup, authentik compares LDAP group membership values with this attribute. In user-based lookup, it compares returned LDAP user DNs with this attribute. When **Sync Group Hierarchy** is enabled, authentik also compares LDAP group membership values with this attribute on authentik groups. |
| **Lookup using user attribute** | Controls how authentik finds a group's members. When enabled, authentik queries user objects using the **Group membership field**. When disabled, authentik reads the **Group membership field** from group objects. | **Object uniqueness field**     | LDAP attribute on users and groups that contains a unique identifier.                                                                                                                                                                                                                                                                                                        |

### User path

**User path** supplies the initial path for synchronized users. The default template is `goauthentik.io/sources/%(slug)s`, where `%(slug)s` is replaced with the source's slug.

Property mappings can change the final path. For example, `authentik default LDAP Mapping: DN to User Path` appends DN components in reverse order, excluding `cn` and `dc` components. Synchronization applies the resulting path to existing users as well as new users, so changing the template or mappings can move users to a different path.

### Delete not found objects

When enabled, authentik searches LDAP using the configured user and group search bases and object filters, then checks the returned **Object uniqueness field** values against existing source connections. It deletes local users or groups whose identifiers are no longer found. User deletion requires **Sync users** to be enabled; group deletion requires **Sync groups** to be enabled.

:::warning Deletion is based on search results
An object does not need to be deleted from the directory to disappear from a search. Changing search bases, filters, read permissions, or the uniqueness field can cause previously synchronized objects to be deleted from authentik. This deletes the actual authentik user or group, not just its connection to the LDAP source.
:::

## Group membership and hierarchy

LDAP synchronization handles two different relationships:

- _Direct user membership_: LDAP relates a user directly to a group, such as `alice` to `backend`.
- _Group hierarchy_: LDAP relates a child group to a parent group, such as `backend` to `engineering`.

```text
engineering (parent group)
|
+-- backend (child group)
    |
    +-- alice
        Direct membership: backend
        Inherited membership: engineering
```

Members of child groups inherit membership in their ancestor groups. A user's effective memberships include both direct and inherited memberships. Inherited membership does not add the user directly to every ancestor group. For more information, see [group hierarchy](../../../groups/index.mdx#hierarchy) and the User object's [`groups` and `all_groups()` properties](../../../user/user_ref.mdx#object-properties).

Membership synchronization requires **Sync groups** to be enabled. authentik can match local users and groups even when they are not connected to this source. For each processed group, synchronization replaces its direct user memberships with the matching users while retaining existing members that lack the configured **User membership attribute**.

### Group-based lookup

With **Lookup using user attribute** disabled, authentik reads the **Group membership field** from each LDAP group (`group -> members`). A typical DN-based configuration uses `member` as the membership field and `distinguishedName` as the **User membership attribute**.

authentik compares each membership value with the configured attribute on authentik users. A matching user becomes a direct member. With **Sync Group Hierarchy** enabled, authentik also compares the values with groups; a matching group creates a child-group relationship. The same `member` attribute can therefore contain both user DNs and group DNs.

For user membership with POSIX schemas, a common configuration uses `memberUid` as the **Group membership field** and `uid` as the **User membership attribute**. If `uid` is not already stored in authentik user attributes, create and assign an LDAP user property mapping for it. `memberUid` identifies users, not nested groups.

### User-based lookup

With **Lookup using user attribute** enabled, authentik searches for each group's members under the user base DN. It uses the **Group membership field**, commonly `memberOf`; for example, it constructs the filter `(memberOf=<group_dn>)` to find users whose LDAP membership attribute refers to that group (`user -> containing groups`). This membership search does not apply the **User object filter**.

The returned LDAP user DNs are matched against the **User membership attribute** on authentik users, normally `distinguishedName`. Matching users become direct members of the group in authentik.

With **Sync Group Hierarchy** enabled, authentik reads the **Group membership field** from LDAP group objects (`group -> containing groups`). A value on `backend` that refers to `engineering` makes `engineering` a parent of `backend`. The field must therefore be meaningful on both users and groups when you use this mode for both membership and hierarchy synchronization.

Recursively resolving effective user membership in LDAP is not the same as preserving the LDAP group hierarchy. See the [Active Directory](../../directory-sync/active-directory/index.mdx) and [FreeIPA](../../directory-sync/freeipa/index.mdx) guides for directory-specific configurations.

### Synchronize the group hierarchy

:ak-version[2026.8]

The **Sync Group Hierarchy** setting requires **Sync groups** to be enabled. Instead of using separate LDAP hierarchy fields, it reuses **Lookup using user attribute**, **Group membership field**, and **User membership attribute**. A membership value creates a hierarchy relationship when the value matches the configured attribute on an authentik group.

The LDAP membership field must contain group references to synchronize a hierarchy. If the matching attribute is not populated automatically on authentik groups, create an LDAP property mapping and assign it under **Group Property Mappings**.

**Additional Parent Group** is separate. It adds the selected authentik group as another parent of imported groups. Hierarchy synchronization preserves this relationship when the additional parent is not connected to this LDAP source.

For example, consider these LDAP objects:

```text
engineering
  member:
    cn=backend,...

backend
  member:
    uid=alice,...
```

With group-based lookup, `member` as the **Group membership field**, `distinguishedName` as the **User membership attribute**, and **Sync Group Hierarchy** enabled, authentik creates the hierarchy shown above.

Alice is a direct member of `backend` and an effective member of `engineering`. Because authentik calculates effective membership through the hierarchy, you do not need to import every transitive user membership.

### Choose a membership setup

Attribute names depend on the LDAP schema. Configure **Sync Group Hierarchy**, **Group membership field**, **User membership attribute**, and **Lookup using user attribute** together by using one complete row from the following table. Combine values from different rows only when your LDAP schema requires a custom configuration.

| If you want to...                                 | Lookup using user attribute | Group membership field               | Sync Group Hierarchy |
| ------------------------------------------------- | --------------------------- | ------------------------------------ | -------------------- |
| Read direct users from each group's member list   | Disabled                    | `member` or schema equivalent        | Disabled             |
| Read memberships from attributes on users         | Enabled                     | `memberOf` or schema equivalent      | Disabled             |
| Preserve nested groups through group member lists | Disabled                    | `member` or schema equivalent        | Enabled              |
| Read parent links from attributes on groups       | Enabled                     | `memberOf` or schema equivalent      | Enabled              |
| Ask AD to resolve recursive user membership       | Enabled                     | AD matching-rule-in-chain expression | Disabled             |

## LDAP source property mappings

LDAP source property mappings map LDAP attributes to authentik properties. See the [property mapping overview](../../property-mappings/index.mdx) for more information.

By default, authentik ships with [pre-configured mappings](#built-in-property-mappings) for the most common LDAP setups. These mappings can be found on the LDAP Source Configuration page in the Admin interface.

Incoming LDAP values can be lists. Synchronization automatically takes the first element of lists returned for top-level properties such as `username`, but values nested under `attributes` retain their types. To store a single value from a list, use the built-in `list_flatten` function. It returns the first element, or `None` for an empty list, and leaves non-list values unchanged. For example:

```python
return {
    # list_flatten is applied automatically to top-level properties.
    "username": ldap.get("uid"),
    "attributes": {
        # Apply list_flatten explicitly to nested attributes.
        "phone": list_flatten(ldap.get("telephoneNumber")),
    },
}
```

The same LDAP source property mapping type is used for both users and groups. A mapping applies to groups only when you assign it under **Group Property Mappings** on the LDAP source. If you use only the built-in group property mappings, synchronized groups retain automatically populated LDAP attributes such as `distinguishedName`. Custom LDAP attributes are copied only when you add a custom group mapping.

### Copy a custom LDAP group attribute

To store a custom LDAP group attribute in an authentik group's `attributes` property, create an **LDAP Source Property Mapping** and assign it to **Group Property Mappings** on the source:

```python
return {
    "attributes": {
        "acl": list_flatten(ldap.get("acl")),
    },
}
```

If your LDAP server stores the value as JSON text and you want authentik to keep it as structured data instead of a string, decode it in the mapping:

```python
import json

raw_acl = list_flatten(ldap.get("acl"))
return {
    "attributes": {
        "acl": json.loads(raw_acl) if raw_acl else None,
    },
}
```

### Built-in property mappings

When you define an LDAP source, its property mappings determine how LDAP properties map to authentik properties. By default, authentik creates the following mappings:

- `authentik default Active Directory Mapping: givenName`
- `authentik default Active Directory Mapping: sAMAccountName`
- `authentik default Active Directory Mapping: sn`
- `authentik default Active Directory Mapping: userPrincipalName`
- `authentik default LDAP Mapping: DN to User Path`
- `authentik default LDAP Mapping: mail`
- `authentik default LDAP Mapping: Name`
- `authentik default OpenLDAP Mapping: cn`
- `authentik default OpenLDAP Mapping: uid`

These mappings support common LDAP configurations.

### Expression data

The following variables are available to LDAP source property mappings:

- `ldap`: A Python dictionary containing data from LDAP.
- `dn`: The object DN.

### Additional expression semantics

To skip synchronization for a specific object, raise the `SkipObject` exception in an LDAP property mapping.

**Example**:

```python
if list_flatten(ldap.get("cn")) == "doNotSync":
    raise SkipObject
```

## Password login

The password stage's **User database + LDAP password** backend authenticates an existing authentik user by binding to LDAP with the user's stored `distinguishedName` and the submitted password. It requires a reachable LDAP server.

Enabling **Update internal password on login** also stores a hash of the password in authentik after a successful LDAP bind. The separate **User database + standard password** backend can use that hash to authenticate the user without contacting LDAP. This can allow users to log in during an LDAP outage, provided that the stored password remains usable and the authentication flow permits local-password authentication. The password stage tries its configured backends in order and stops at the first success; a successful local-password check does not validate the password with LDAP.

The **Update internal password on login** setting is disabled by default for new sources. Disabling it stops future LDAP logins from updating the local password; it does not remove a password already stored in authentik.

Consider the following before enabling local password updates:

- A successful LDAP login overwrites any different password stored for that user in authentik.
- Changing a password in LDAP does not immediately invalidate the stored authentik password. During user synchronization, authentik checks AD's `pwdLastSet` and FreeIPA's `krbLastPwdChange` when those attributes are present. Synchronization marks the local password as unusable for newly created users. It also marks the local password as unusable when the directory timestamp is at least as recent as the local password-change timestamp. Without these attributes, this synchronization check does not invalidate the local password.
- Local-password authentication does not perform a live check of directory password policies or account status. Evaluate this behavior against your security requirements.

## Run a synchronization

Saving an LDAP source queues a synchronization in the background. To check its progress, open the source's **Overview** tab and review **Sync status**.

To start another synchronization manually:

1. Open the source's **Overview** tab.
2. Under **Schedules**, locate the task with the description **Sync LDAP source.**
3. Click its play icon, labeled **Run scheduled task now**.
