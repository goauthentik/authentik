## What it can do

- Retrieve host information and report it to authentik for [device compliance](../../device-compliance/index.mdx).
- Connect to Linux hosts with authentik credentials through [SSH authentication](../../authentik-agent/device-authentication/ssh-authentication.mdx).
- Authenticate to CLI applications with authentik credentials through [CLI application authentication](../../authentik-agent/device-authentication/cli-app-authentication/index.mdx).
- Log in to the device with authentik credentials through [local device login](../device-authentication/local-device-login/linux.mdx).

## Prerequisites

You must [configure your authentik deployment](../configuration.mdx) to support the authentik Agent.

## Create an enrollment token

If you already have an enrollment token, skip to [Install the authentik Agent on Linux](#install-the-authentik-agent-on-linux).

1. Log in to authentik as an administrator and open the authentik Admin interface.
2. Navigate to **Endpoint Devices** > **Connectors**.
3. Click on the authentik Agent connector that you created when [configuring your authentik deployment](../configuration.mdx) to support the authentik agent.
4. Under **Enrollment Tokens**, click **New Enrollment Token**, and configure the following settings:
    - **Token name**: Provide a descriptive name for the token.
    - **Device group _(optional)_**: Select a device access group to add the device to after enrollment.
    - **Expiring _(optional)_**: Set whether the enrollment token expires.
5. Click **Create**.
6. _(Optional)_ Click the **Copy** icon in the **Actions** column. You need this value to [join the device to an authentik domain](#join-the-device-to-an-authentik-domain).

## Install the authentik Agent on Linux

The authentik Agent is available in two packages. Install one of them, depending on the device:

| Package                   | For                                   | Contents                                                                                                               |
| ------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `authentik-agent-desktop` | Workstations with a graphical desktop | The [authentik Agent app](../desktop-app.mdx), which runs the user agent. Requires WebKitGTK, GTK 3, and AppIndicator. |
| `authentik-agent`         | Servers and devices without a desktop | The user agent, run as a systemd user service.                                                                         |

The two packages can't be installed together.

Follow these steps to install the authentik Agent on your Linux device:

<Tabs defaultValue="Debian-based">
<TabItem value="Debian-based">

1. Open a Terminal session and install the required GPG key:

```sh
curl -fsSL https://pkg.goauthentik.io/keys/gpg-key.asc | sudo gpg --dearmor -o /usr/share/keyrings/authentik-keyring.gpg
```

2. Add the repository:

```sh
echo "deb [signed-by=/usr/share/keyrings/authentik-keyring.gpg] https://pkg.goauthentik.io stable main" | sudo tee /etc/apt/sources.list.d/authentik.list
```

3. Update your repositories and install the authentik Agent packages:

```sh
sudo apt update
sudo apt install authentik-cli authentik-sysd authentik-agent-desktop
```

On a server, install `authentik-agent` instead of `authentik-agent-desktop`.

4. _(Optional)_ To enable [SSH server authentication and local device login](#join-the-device-to-an-authentik-domain), install two additional packages:

```sh
sudo apt install libnss-authentik libpam-authentik
```

5. Confirm that the authentik Agent is installed by opening a terminal window and entering the following command: `ak version`

    You should see output that starts with: `authentik Agent CLI: <version_number>`

:::note Headless server
With the `authentik-agent` package, start the user agent for your user:

```bash
systemctl --user enable --now ak-agent
```

:::

</TabItem>
<TabItem value="RedHat-based">

1. Open a Terminal session and run the following command to add the authentik repo and associated GPG key:

```bash
# This overwrites any existing configuration in /etc/yum.repos.d/authentik.repo
cat <<EOF | sudo tee /etc/yum.repos.d/authentik.repo
[authentik]
name=authentik
baseurl=https://pkg.goauthentik.io
enabled=1
gpgcheck=1
gpgkey=https://pkg.goauthentik.io/keys/gpg-key.asc
EOF
```

2. Run the following commands to refresh metadata and install the authentik Agent packages:

```bash
sudo yum install -y authentik-cli authentik-sysd authentik-agent-desktop
```

On a server, install `authentik-agent` instead of `authentik-agent-desktop`.

3. _(Optional)_ To enable [SSH server authentication and local device login](#join-the-device-to-an-authentik-domain), install two additional packages:

```sh
sudo yum install -y libnss-authentik libpam-authentik
```

4. Confirm that the authentik Agent is installed by opening a terminal window and entering the following command: `ak version`

    You should see output that starts with: `authentik Agent CLI: <version_number>`

:::note Headless server
With the `authentik-agent` package, start the user agent for your user:

```bash
systemctl --user enable --now ak-agent
```

:::

</TabItem>
<TabItem value="Arch Linux">

The authentik Agent is available as Arch Linux packages, but not from a pacman repository.

1. Download the packages for the latest version and your architecture from [pkg.goauthentik.io](https://pkg.goauthentik.io) or from the [GitHub releases](https://github.com/goauthentik/platform/releases): `authentik-cli`, `authentik-sysd`, and `authentik-agent-desktop` (or `authentik-agent` on a server).
2. Install the packages:

```sh
sudo pacman -U authentik-cli-*.pkg.tar.zst authentik-sysd-*.pkg.tar.zst authentik-agent-desktop-*.pkg.tar.zst
```

3. _(Optional)_ To enable [SSH server authentication and local device login](#join-the-device-to-an-authentik-domain), also download and install `libnss-authentik` and `libpam-authentik`, then [configure PAM](#configure-nss-and-pam).
4. Confirm that the authentik Agent is installed by opening a terminal window and entering the following command: `ak version`

    You should see output that starts with: `authentik Agent CLI: <version_number>`

To update the authentik Agent, download and install the packages for the new version.

:::note Headless server
With the `authentik-agent` package, start the user agent for your user:

```bash
systemctl --user enable --now ak-agent
```

:::

</TabItem>

## Join the device to an authentik domain

Joining the device to an authentik domain is what enrolls it with your authentik deployment and issues it a device token. This step is required for [device compliance features](../../device-compliance/index.mdx), for the device [accepting SSH connections](../../authentik-agent/device-authentication/ssh-authentication.mdx), and for local device login.

1. Open a Terminal session and run the following command:

```sh
sudo ak-sysd domains join <deployment_name> --authentik-url https://authentik.company
```

- `deployment_name` identifies the authentik deployment on the device.
- `https://authentik.company` is the fully qualified domain name of the authentik deployment.

2. Enter your [enrollment token](#create-an-enrollment-token) when prompted.
3. After you enter the token, authentik enrolls the device. The device appears on the [Devices page](../../manage-devices.mdx) after it [checks in](../../device-compliance/device-reporting.mdx).

## Configure NSS and PAM

SSH server authentication and local device login need the `libnss-authentik` and `libpam-authentik` packages, and NSS and PAM must use them.

<Tabs defaultValue="Debian-based">
<TabItem value="Debian-based">

The packages configure NSS and PAM when they're installed. No further steps are needed.

</TabItem>
<TabItem value="RedHat-based">

Select the `authentik` authselect profile, which the `libpam-authentik` package installs:

```sh
sudo authselect select authentik
```

The profile supports the usual authselect features. For example, to create home directories when users log in for the first time, select `authentik with-mkhomedir` instead. This requires the `oddjob-mkhomedir` package.

</TabItem>
<TabItem value="Other distributions">

On Arch Linux, the `libnss-authentik` package configures NSS. On other distributions, edit `/etc/nsswitch.conf` to include `authentik` for `passwd`, `group`, and `shadow`:

```text title="/etc/nsswitch.conf"
passwd:         files systemd authentik
group:          files systemd authentik
shadow:         files systemd authentik
```

Then configure PAM. Add the following lines to the PAM configuration that your login and SSH services include, for example `/etc/pam.d/system-auth` on Arch Linux. Add the `auth` line before `pam_unix.so` in the `auth` section, and the `session` line before `pam_unix.so` in the `session` section.

```text
auth      [success=done default=ignore]   pam_authentik.so
session   [success=ok default=ignore]     pam_authentik.so
```

:::warning
Keep a root shell open while you edit PAM configuration, so that you can undo a change that prevents logins.
:::

</TabItem>
</Tabs>

`pam_authentik` only handles authentik users. Local users continue to log in with their local password.

## User names and IDs

The authentik Agent makes authentik users and groups available on the device. Their names and IDs are derived as follows:

- **User names**: authentik usernames are converted to lowercase, and `@`, `/`, and `:` are replaced with `-`. For example, `Jane.Doe@Company.com` becomes `jane.doe-company.com`. Users log in with the converted name.
- **User IDs**: the value of the user's `uidNumber` attribute, or the connector's **NSS User ID offset** plus the user's ID in authentik.
- **Primary group IDs**: the value of the user's `gidNumber` attribute, or the same value as the user ID.
- **Group IDs**: the value of the group's `gidNumber` attribute, or the connector's **NSS Group ID offset** plus the group's ID in authentik.

Set `uidNumber` and `gidNumber` as strings, for example:

```yaml
uidNumber: "20001"
gidNumber: "20001"
```

Users and groups with an ID below 1000 aren't made available. Home directories are `/home/<user name>`, and the shell is `/bin/bash`.

:::warning Conflicting users
If two or more authentik users have the same converted user name or the same user ID, none of them are made available on the device, and they can't log in. For example, this happens for users named `Alice` and `alice`. Rename one of the users, or set unique `uidNumber` attributes.
:::

To check whether a user is available, run `getent passwd <user name>`.

## Enable SSH client authentication and CLI application authentication

To enable [initiating SSH connections](../../authentik-agent/device-authentication/ssh-authentication.mdx) and [CLI application authentication](../../authentik-agent/device-authentication/cli-app-authentication/index.mdx), the device must be connected to an authentik deployment. To do so, follow these steps:

1. Open a Terminal session and run the following command:

```sh
ak config setup --authentik-url https://authentik.company
```

2. Your default browser opens the authentik login page. After you authenticate, the authentik Agent is configured.

## Check version of installed components

You can check the version of all installed authentik components by running the following command:

```bash
ak version
```

## View logs

authentik Agent logs are available via the systemd journal (`journalctl`) or `syslog`, depending on the distribution. For example:

- System agent: `journalctl -u ak-sysd`
- User agent from the `authentik-agent` package: `journalctl --user -u ak-agent`
