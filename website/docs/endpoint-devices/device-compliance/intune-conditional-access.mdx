authentik can be configured to restrict access to specific services so that only devices that are managed by Microsoft Intune, and that are compliant in Intune, are allowed.

This works as follows:

1. Intune deploys a client certificate to each device. The certificate contains the device's Intune device ID.
2. When a user accesses authentik, their browser presents the certificate.
3. The [Endpoint stage](../../add-secure-apps/flows-stages/stages/endpoint/index.mdx) verifies the certificate against the certificate authorities that are configured on the [Microsoft Intune connector](./connectors/microsoft-intune.mdx), and uses the device ID to find the device among the devices that were imported from Intune.
4. A policy checks the compliance state of the device.

:::info
The Endpoint stage only identifies the device. It does not check whether the device is compliant in Intune, or whether the device belongs to the user who is logging in. Use a [policy](#require-a-compliant-device) for these checks.
:::

## Prerequisites

- The [Microsoft Intune connector](./connectors/microsoft-intune.mdx) must be configured in authentik, and must have synchronized your devices.
- A private certificate authority that issues certificates to devices through Intune, such as [Microsoft Cloud PKI](https://learn.microsoft.com/en-us/intune/cloud-pki/) or Active Directory Certificate Services.
- authentik must receive client certificates, either from a reverse proxy or by terminating TLS itself. Refer to the [Mutual TLS stage documentation](../../add-secure-apps/flows-stages/stages/mtls/index.mdx#reverse-proxy-configuration) for more information.
- Device names must be unique in Intune. Refer to [Device matching](./connectors/microsoft-intune.mdx#device-matching) for more information.

## Configure Intune and devices

Create a SCEP or PKCS certificate profile in Intune and assign it to every device that requires conditional access. Refer to the [Microsoft documentation for certificate profiles](https://learn.microsoft.com/en-us/intune/intune-service/protect/certificates-profile-scep) for more information.

Configure the certificate profile with the following settings:

- **Certificate type**: `User`. Browsers only use certificates from the user's certificate store.
- **Subject alternative name**: add an attribute of type `URI` with the value `ID:Intune:GUID:{{DeviceId}}`.
- **Extended key usage**: `Client Authentication`

:::warning Subject alternative name is required
authentik rejects certificates that do not have a subject alternative name, and only reads the device ID from a URI in the format `ID:<name>:GUID:<device ID>`. A certificate that only contains the device ID in its subject is not accepted.
:::

authentik matches the device ID against both the Intune device ID and the Entra ID device ID of the imported devices. You can therefore also use `ID:Intune:GUID:{{AAD_Device_ID}}` for devices that are joined to or registered with Entra ID.

## Configure authentik

### Add the certificate authority to the connector

1. Export the certificate of the certificate authority that issues the device certificates in PEM format.
2. Log in to authentik as an administrator and open the authentik Admin interface.
3. Navigate to **System** > **Certificates** and click **Import Existing**.
4. Provide a name, paste the certificate into the **Certificate** field, and leave the **Private Key** field empty.
5. Click **Import**.
6. Navigate to **Endpoint Devices** > **Connectors** and edit the Microsoft Intune connector.
7. Under **Certificate authorities**, select the certificate that you imported.
8. Click **Update**.

:::warning Use the issuing certificate authority
Select the certificate authority that directly issues the device certificates. If you use an intermediate certificate authority, selecting only the root certificate authority is not sufficient, because authentik only receives the device's certificate.
:::

If no certificate authorities are selected on the connector, the **Client Certificates** of the active [brand](../../customize/branding/index.mdx#client-certificates) are used. If authentik terminates TLS itself, the certificate authority must also be added to the brand, because authentik otherwise does not request a certificate from the browser.

### Bind Endpoint stage to flow

The flow must have an [Endpoint stage](../../add-secure-apps/flows-stages/stages/endpoint/index.mdx) bound to it. This configuration applies to a specific flow, such as an authentication flow.

1. Log in to authentik as an administrator and open the authentik Admin interface.
2. Navigate to **Flows and Stages** > **Flows**.
3. Select the flow that you want to modify.
4. Open the **Stage Bindings** tab and click **Create and bind stage**.
5. Select **Endpoint Stage** as the stage type, click **Next**, and configure the following settings:
    - **Name**: provide a name for the stage
    - **Connector**: select the Microsoft Intune connector
    - **Mode**: set to `Device required`
6. Click **Next**.
7. Select the order for the stage. Ensure that this places the Endpoint stage in the flow wherever you want device access to be checked.
8. Click **Finish**.

With the `Device required` mode, the flow is denied if the browser does not present a valid certificate, or if the certificate does not belong to a device that was imported from Intune.

### Require a compliant device

To only allow devices that are compliant in Intune, add a [Deny stage](../../add-secure-apps/flows-stages/stages/deny/index.mdx) with an expression policy after the Endpoint stage.

1. On the **Stage Bindings** tab of the flow, click **Create and bind stage**.
2. Select **Deny Stage** as the stage type, click **Next**, and configure the following settings:
    - **Name**: provide a name for the stage
    - **Deny message**: provide a message explaining why access was denied
3. Click **Next**.
4. Select the order for the stage. Ensure that this number is higher than the order of the Endpoint stage.
5. Click **Finish**.
6. Expand the Deny stage that you just created and click **Create and bind Policy**.
7. Select **Expression policy** as the policy type, click **Next**, and configure the following settings:
    - **Name**: provide a descriptive name for the policy
    - **Expression**:

        ```python
        flow_plan = request.context.get("flow_plan")
        device = flow_plan.context.get("device") if flow_plan else None
        if device is None:
            return True
        intune = device.facts.data.get("vendor", {}).get("intune.microsoft.com", {})
        if intune.get("compliance_state") != "compliant":
            ak_message("This device is not compliant in Microsoft Intune.")
            return True
        return False
        ```

        :::info Deny stage
        Because this is a deny stage, the policy must evaluate true when a requirement is not met.
        :::

8. Click **Next** and then click **Finish**.

You can extend the expression with other [device facts](./connectors/microsoft-intune.mdx#device-facts). For example:

- To also allow devices that are within their compliance grace period, check for `intune.get("compliance_state") not in ("compliant", "inGracePeriod")`.
- To only allow devices that are owned by your organization, check for `intune.get("managed_device_owner_type") != "company"`.
- To ensure that the certificate was issued to the device whose facts are evaluated, compare the device ID from the certificate with the Intune device ID:

    ```python
    certificate = flow_plan.context.get("certificate", {})
    uris = certificate.get("san", {}).get("UniformResourceIdentifier", [])
    device_ids = [uri.rpartition("GUID:")[2].lower() for uri in uris]
    if intune.get("id", "").lower() not in device_ids:
        return True
    ```

:::note Compliance changes are not immediate
authentik synchronizes devices from Intune every 15 minutes. A change to the compliance state of a device in Intune only takes effect in authentik after the next synchronization.
:::

## Troubleshooting

- **Certificate required but no certificate was given**: the browser did not present a certificate, or the certificate could not be verified. Check that the certificate is installed in the user's certificate store, that it has a subject alternative name and the `Client Authentication` extended key usage, that it was issued by the certificate authority that is selected on the connector, and that your reverse proxy forwards client certificates to authentik.
- **Failed to find device**: the certificate is valid, but no imported device has the device ID from the certificate. Check that the subject alternative name uses the format `ID:Intune:GUID:{{DeviceId}}`, and that the device is shown under **Endpoint Devices** > **Devices**.
