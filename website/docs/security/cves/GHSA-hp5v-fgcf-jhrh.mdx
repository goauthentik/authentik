# GHSA-hp5v-fgcf-jhrh

_Reported by [@AllanzoDaizen](https://github.com/AllanzoDaizen)_

## Request Smuggling via Forwarded Hop-by-Hop Headers

### Summary

A single request could be processed as two, and any client could supply headers that are only accepted from trusted proxies.

### Patches

authentik 2026.5.9 and 2026.8.7 fix this issue.

### Impact

**All deployments are affected.**

An attacker with network access to the server could take over the sessions of other active users. Where certificate login is used, they could also log in as any user whose certificate they have.

### Workarounds

None. A reverse proxy in front of the server does not reliably prevent this issue.
