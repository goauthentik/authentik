## What is Google Cloud Workforce Identity Federation?

Google Cloud Workforce Identity Federation allows users from an external identity provider to access Google Cloud resources using their existing credentials. This guide configures SAML sign-in with authentik and uses group membership to assign access through Google Cloud IAM.

## Preparation

The following placeholders are used in this guide:

- `authentik.company` is the FQDN of the authentik installation.
- `<organization_id>` is the Google Cloud organization ID.
- `<pool_id>` is a globally unique workforce identity pool ID.
- `<provider_id>` is the workforce identity pool provider ID.
- `<project_id>` is the project to which users require access.
- `<metadata_path>` is the local path to the metadata XML downloaded from authentik.

You need a Google Cloud organization and an account with **IAM Workforce Pool Admin** (`roles/iam.workforcePoolAdmin`) on that organization. To assign project access, you also need **Project IAM Admin** (`roles/resourcemanager.projectIamAdmin`) on the target project, or equivalent permissions.

Install and initialize the [Google Cloud CLI](https://docs.cloud.google.com/sdk/docs/install-sdk/) with `gcloud init`. Enable the IAM and Resource Manager APIs. If you need to enable APIs, your account requires **Service Usage Admin** (`roles/serviceusage.serviceUsageAdmin`) on the project. Configure the organization's Essential Contacts as described in Google's [setup requirements](https://docs.cloud.google.com/iam/docs/configuring-workforce-identity-federation).

Create an authentik group named `gcp-readers` and add the users who should have access.

:::info
This guide uses an organization-level workforce identity pool. The same SAML integration can be used across projects; IAM role assignments determine which resources users can access. Google Workspace and Cloud Identity account federation use a separate configuration.
:::

### Create a workforce identity pool

1. Sign in to the Google Cloud CLI with the account authorized to manage workforce pools.
2. Create the pool, replacing the placeholders before running the command:

    ```bash
    gcloud iam workforce-pools create "<pool_id>" \
      --organization="<organization_id>" \
      --display-name="authentik" \
      --location=global
    ```

:::note
After granting the workforce pool administrator role, allow time for IAM propagation before creating the pool. Changes typically take 2 minutes and can take 7 minutes or longer. An immediate retry can return `iam.workforcePools.create` permission denied even after the role grant succeeds.
:::

## authentik configuration

To support the integration of Google Cloud Workforce Identity Federation with authentik, you need to create an [application/provider pair](/docs/add-secure-apps/applications/manage_apps/#create-an-application-and-provider-pair) in authentik.

### Create an application and provider

1. Log in to authentik as an administrator and open the authentik Admin interface.
2. Navigate to **Applications** > **Applications** and click **New Application** to open the application wizard.
    - **Application**: provide a descriptive name and configure the following settings.
        - Under **UI settings**, set **Launch URL** to `https://auth.cloud.google/signin/locations/global/workforcePools/<pool_id>/providers/<provider_id>?continueUrl=https://console.cloud.google/`.
    - **Choose a Provider type**: select **SAML Provider**.
    - **Configure the Provider**: provide a name, select the authorization flow, and configure the following settings.
        - Set **ACS URL** to `https://auth.cloud.google/signin-callback/locations/global/workforcePools/<pool_id>/providers/<provider_id>`.
        - Set **Audience** to `https://iam.googleapis.com/locations/global/workforcePools/<pool_id>/providers/<provider_id>`.
        - Set **Service Provider binding** to **HTTP POST**.
        - Under **Advanced protocol settings**, select an available RSA **Signing Certificate**. Enable **Sign responses** and **Sign assertions**, using **RSA-SHA256** and **SHA256** for the signature and digest algorithms.
        - Set **NameID Property Mapping** to `authentik default SAML Mapping: User ID`.
        - Ensure that **Property mappings** includes `authentik default SAML Mapping: User ID` and `authentik default SAML Mapping: Groups`.
    - **Configure Bindings**: bind the `gcp-readers` group to restrict application access to its members.
3. Save the new application and provider.

:::note User identifier
Google Cloud uses the SAML NameID as the user's subject identifier. Keep the NameID mapping stable after assigning access. Leave the authentik IdP issuer at its default; the Google Cloud audience belongs in **Audience**, not **EntityID/Issuer override**.
:::

### Download the identity provider metadata

1. Navigate to **Applications** > **Providers** and open the provider that you created.
2. Under **Related objects** > **Metadata**, click **Download**.
3. Note the downloaded file's full path. Use this path for `<metadata_path>` in the next section. Keep the path quoted if the filename contains spaces or parentheses.

## Google Cloud configuration

### Create the SAML provider

Run the following command, replacing the placeholders with your pool ID, provider ID, and metadata file path:

```bash
gcloud iam workforce-pools providers create-saml "<provider_id>" \
  --workforce-pool="<pool_id>" \
  --display-name="authentik" \
  --idp-metadata-path="<metadata_path>" \
  --attribute-mapping="google.subject=assertion.subject,google.groups=assertion.attributes['http://schemas.xmlsoap.org/claims/Group']" \
  --attribute-condition="'gcp-readers' in google.groups" \
  --location=global
```

The mapping uses the SAML NameID for `google.subject` and authentik's default Groups attribute for `google.groups`. The condition permits only members of `gcp-readers` to authenticate through this provider. Allow a few minutes for the provider to become available.

### Assign project access

Grant the federated group **Browser** for federated console access and the additional IAM roles required for its resources. For example, the following commands grant Browser and Compute Viewer on a project:

```bash
gcloud projects add-iam-policy-binding "<project_id>" \
  --member="principalSet://iam.googleapis.com/locations/global/workforcePools/<pool_id>/group/gcp-readers" \
  --role="roles/browser"

gcloud projects add-iam-policy-binding "<project_id>" \
  --member="principalSet://iam.googleapis.com/locations/global/workforcePools/<pool_id>/group/gcp-readers" \
  --role="roles/compute.viewer"
```

If you use another group name, update the authentik group, provider attribute condition, and IAM principal identifiers to match.

## Configuration verification

Open the Google Cloud application from the authentik User interface. Authenticate if prompted and confirm that the Google Cloud federated console opens. Select the project and verify that the user can access the resources permitted by its IAM roles. To view Compute Engine resources, the project must have the Compute Engine API enabled.

Test the Launch URL in a private browser session with a user outside `gcp-readers` and confirm that access is denied. If a permitted user receives `The given credential is rejected by the attribute condition`, verify that the user belongs to `gcp-readers` and that the provider includes the default Groups property mapping. Start a new sign-in after saving changes.

The federated console supports a subset of Google Cloud products and features. Check the [supported products and limitations](https://docs.cloud.google.com/iam/docs/federated-identity-supported-services) for the services you intend to use.
